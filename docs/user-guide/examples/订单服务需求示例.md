# 订单服务需求示例

此文档演示需求写法。请先替换为实际骨架中的接口、字段和数据库约束，再导入 RECAST。该示例不附带可直接运行的目标骨架。

## 业务目标

基于已导入的 OrderService 骨架，补全多租户订单创建和查询功能。使用 C# 与 .NET 8，保留现有项目结构、对外接口签名和仓储端口。参考工程仅用于借鉴实现，不能覆盖目标项目的业务约束。

## 功能与约束

1. 每张订单必须关联租户标识。服务从已验证的调用上下文读取租户，不信任请求正文里自行传入的租户值。
2. 创建订单至少包含一个商品项；数量为正整数，单价不得为负。金额使用 decimal，订单总额为商品金额之和，禁止使用浮点金额运算。
3. 创建请求包含幂等键。相同租户与相同幂等键、相同请求内容重复提交时，返回同一订单；同键不同内容返回明确的冲突错误。不同租户的幂等键相互隔离。
4. 查询订单时，仓储查询必须带租户条件。订单不属于当前租户时，按照骨架约定返回未找到，不能泄露其他租户的数据或存在性。
5. 业务错误、参数错误和系统错误按现有接口规范返回，禁止在外部响应中泄露堆栈、凭据或内部路径。
6. 数据访问通过现有仓储端口完成，不硬编码数据库连接信息，不新增与当前技术栈无关的运行依赖。

## 验收场景

- 正常创建包含多个商品项的订单，金额计算准确，可用当前租户查询。
- 空商品列表、数量为零或负数、负单价、缺少租户上下文均被拒绝。
- 相同租户相同请求重复提交得到同一订单，不重复持久化。
- 相同幂等键但请求内容不同，返回明确冲突。
- 不同租户可以使用相同幂等键，互不影响。
- 跨租户查询无法获取订单；普通租户不能伪造上下文切换租户。
- 仓储失败时返回符合现有规范的错误，不产生半完成的订单。
