# 技术债与验收条件

按风险和修改场景安排后续工作。关闭一项时，在同一 PR 附上复现命令、测试结果或平台设置证据。

| 优先级 | 归属与问题 | 关闭条件 |
| --- | --- | --- |
| 高 | 仓库管理员：本地 workflow 只定义可报告的状态。 | 在受保护的主分支设置 PR 必需、至少一位其他评审者批准、`Repository quality` 必需；用失败检查的测试 PR 确认平台拒绝合并。 |
| 高 | 工具链：首轮分支的开发审计曾报告打包链公告，移植后按主线锁文件复测。 | 复跑 `npm audit`，审查受影响的构建/发布路径，完成兼容升级和 Windows/Linux VSIX 验收。详见[静态分析](static-analysis.md)。 |
| 高 | 索引与宿主：内存存储能验证版本和权限，无法证明真实 SQL、向量索引和升级后的持久性。 | 变更 schema、向量维度或激活逻辑时，按[部署说明](../seekdb-docker-setup.md)建独立测试库，导入两次、断开再连接，复查指定版本、活动版本和向量检索。保留数据库名、版本及结果。 |
| 中 | 扩展发布：CommonJS 打包期间 esbuild 提示部分路径中的 `import.meta` 不可用。包清单标注 MIT，扩展目录尚无可随包交付的授权文件。 | 从干净 VSIX 安装并在宿主验证 worker、适配后端和检索；发布负责人确认分发授权并补齐适用的许可文件。 |
| 中 | 核心工作区：遗留 lint 警告、较大的存储适配器和索引编排代码提高评审成本。工作区沿用各自 TS 配置，部分排除包内测试；实验驱动脚本的 TS 类型尚未纳入统一门禁。 | 按模块在变更时清理并降低警告上限。拆分前加行为测试。对需要纳入的脚本/测试建立独立 TS 检查并记录诊断数。 |
| 中 | 验证与上线：Maven、特定 runner、真实模型及 VS Code 宿主测试各需额外环境。 | 对涉及这些路径的发布，记录工具/模型版本、夹具、用例结果及回滚结果。每个真实模型/编译器测试的运行条件见[测试策略](../testing/testing-strategy.md)。 |
| 低 | 归档实验与产品开发的依赖和测试入口已分开。 | 新增产品回归输入时只保留可复现的源码夹具；在归档 checkout 按[复现说明](../archive.md)获取实验数据和历史脚本。 |
