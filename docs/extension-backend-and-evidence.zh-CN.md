# 扩展后端与验收边界

日常从仓库根目录运行 `npm run dev:extension`。启动器准备依赖服务并构建扩展；工作台在可信工作区启动扩展自带的适配后端。完整安装和模型配置见[根目录 README](../README.md)。

## 后端连接

扩展为目标工程启动独立子进程，使用系统分配的空闲端口，并通过进程通信取得实际地址。目标根目录、能力和身份令牌经过校验后才发送请求。实际地址及启动失败原因见 **输出 → RECAST**。

同一后端的并发启动请求会合并。窗口关闭时只清理其拥有的进程；目标或配置变更时，宿主按当前任务状态协调后端切换。不要另行启动一个未经配置匹配的适配后端来覆盖工作台状态。

设置面板保存的 Key 位于 VS Code SecretStorage，宿主按请求读取并交给已验证的后端，不写入仓库和 Webview 配置。服务已连接不代表模型已授权；模型请求失败时应核对提供方、协议、模型名称和 Key。

## 导入与取证

目标和参考仓库通过独立导入任务展示阶段、进度及失败原因。结构索引和功能建模是不同阶段；只有目录与文件结构不代表已得到可供流水线使用的模型。数据库初始化恢复见[索引初始化说明](index-initialization-recovery.zh-CN.md)。

宿主绑定目标工程、只读参考视图、允许写入范围和编译命令。模型不能自行扩大文件权限、修改验收规则或把公共健康检查当作验证通过。

## 验收

编译成功表示构建检查通过。行为验证由 Host 运行测试并读取执行及覆盖率证据，区分生产缺陷、测试环境故障与结论待定。被修改的失败测试保留原始证据，仅在必要时进行一次独立纠错检查。

生成测试随项目交付，在最终目录重新执行；操作方法与限制见[生成测试交付](retained-tests.zh-CN.md)。模型输出超限时的处理见[自动恢复](output-limit-recovery.zh-CN.md)。

维护检查使用 `npm test`、`npm run test:scripts`、`npm run test:verifier`。在线模型和真实编译器用例需要显式启用并准备相应环境；离线回归不代表已经通过企业业务验收。历史实验成绩及过程记录见[归档说明](archive.md)。
