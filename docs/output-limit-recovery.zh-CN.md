# 模型输出超限与自动恢复

`exceed output tokens` 等错误表示一次模型生成触及输出预算。单次输出预算、上下文容量和任务执行时限分别生效；增加任务时限不会自动增加单次输出预算。

## 系统如何处理

- Translator 与项目 Integration Agent 会保留同一份私有执行副本中的已执行修改，重新读取当前文件，要求模型使用小段补丁、单文件或单个符号的工具调用继续完成剩余需求。
- Analyzer 会重试并要求完整、精简的计划；仍未生成可用计划时，沿用已有的需求直实现 Translator 兜底，不接受半截计划。
- Verifier 会丢弃整条被截断的回复，包括其中看似完整的工具调用，从最后有效的对话与工具结果重新请求。已执行测试、历史失败证据和纠错复核规则继续保留。
- 默认每次超限调用最多额外重试 3 次，不重置原任务的时限。Translator 的编译修复轮数和输出超限重试分别计数，所有实际调用都会记录。
- 续接指令要求先使用小段修改；连续超限后进一步缩小单次修改。它不会缩减需求、跳过测试或把未完成实现标成成功。

Translator 完整结束后，才把通过原有文件权限检查的修改应用到输出项目，并继续编译及正常验收。在超限重试阶段，执行副本中的修改不构成已验收的项目交付。

## 用户看到什么

执行日志会显示“单次输出达到 Token 上限，正在以小步修改续接”，以及当前重试次数。成功后继续执行；持续超限会显示明确原因，可使用已有的失败模块重试入口。

如果服务商明确拒绝输出参数（例如 `max_tokens must be less than or equal to ...`），系统会提示检查模型、API 地址和服务商允许的单次输出上限，不会原样反复请求。认证失败、上下文容量耗尽、权限失败、取消及超时不按输出截断处理。

续接不会把上一轮的最终消息当成本轮完成依据，也不会突破生产文件、只读历史仓库和验收标准的访问边界。

## 验证范围

自动化故障注入覆盖：先写入部分代码后超限、进程退出码为零但报告生成失败、计划截断、集成阶段新增文件、持续超限、参数不兼容、无完成消息、越权写入、恢复后行为仍错误、取消及原时限到期。测试使用真实子进程与 Node.js 编译/行为检查，未调用在线模型。
