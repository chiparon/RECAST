# ADR-001　由扩展宿主确定模块翻译范围

**状态**　记录单模块翻译的已实施决策。默认“整个项目”由宿主管理独立副本和 LangGraph 状态流；项目级恢复和发布边界见[项目流水线](../architecture/system-overview.md)。

**背景**　工作台会同时展示目标模块、历史候选和异步返回的检索结果。用户可能在准备与开始之间修改文件或重新选择模块。直接沿用页面传来的路径会让旧选择影响当前工作区。

**决策**　宿主从当前目标模块和明确的关联依赖导出可写文件，按实际选择的 1–3 个历史候选建立只读上下文。其余可见依赖保持只读。准备时记录目标文件哈希，启动时再检查选择和文件状态。工作区后端校验 Bearer 令牌。用户执行的是准备好的作用域，后续操作携带该次运行的 ID。

**取舍**　若让页面提交最终文件列表，调用接口会更短，但页面无法可靠感知未保存编辑和并发选择。采用宿主快照后，页面只需传递选择和操作。文件变更后用户需要重新准备。模型新增上下文仍受原可写范围约束。直接实现模式沿用同一目标文件边界。

**验证**　重点回归非首个目标文件变化、选择在异步等待时切换，以及服务可能已接受请求但响应丢失时的重试行为。[实现](../../apps/vscode-extension/src/module-translation-handoff.ts)、[交接测试](../../apps/vscode-extension/src/module-translation-handoff.test.ts)、[作用域测试](../../apps/vscode-extension/src/module-translation-scope.test.ts)

改变写入授权方、运行恢复语义或跨服务协议时，在同一 PR 提交后续 ADR，说明变更驱动、采用和舍弃的方案、兼容性、验证方法，以及它取代的决定。
