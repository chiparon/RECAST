# 项目级全自动流水线

当前默认入口是 VS Code 工作台的「整个项目」。导入目标骨架、可选历史仓，填写需求后点击「开始执行」，由扩展宿主持有运行；关闭或切换 Webview 不会中断任务。

## 实际执行链路

1. 等待导入后的项目建模，固定活动索引和源文件哈希，在扩展存储目录创建独立工程副本。
2. 依赖排序、合并循环依赖、补齐未归属的生产文件；Integration Plan Agent 生成 Global Protocol。
3. 使用现有检索和模型重排链路，按本次请求自动选择 1～3 份互补历史参考并保留证据；没有参考时依据公共需求直接实现。自动选择失败会显式报错，不把普通排序结果冒充自动选择。
4. 创建宿主历史视图，调用现有 CodexWorkspaceTranslationRuntime 的 Analyzer / Translator，传递需求、模块协议、历史视图与宿主限定的写入范围。
5. 宿主编译通过后在独立验证副本运行现有函数组 Verifier，保留各模块的测试修订记录，每次验证刷新当前全部生产源码；生成测试不混入交付项目。生产缺陷交回同一 Translator，最多五轮验证。测试环境故障和不确定结论保留为验证缺口，不据此修改生产代码。
6. 模块生成后主动运行项目 Integration，检查完整生产代码、公共需求和跨模块调用链，允许在既有源码范围新增兼容生产文件。
7. 对最终组装项目重新编译、运行可选固定验收命令，并重新执行模块 Verifier。Integration 新增的生产文件也纳入最终函数发现。最终验证记录绑定整个输出项目的文件哈希。
8. 确认生产修改范围、保护文件和验收快照未变化后，在输出副本提交并保存 JSON / Markdown 报告。完整项目编译或固定测试失败时，最多追加两轮 Integration 修复。

编译通过但行为验证存在环境问题或未确定项时，结果只能是 `compilation-only`。最终 Verifier 仍确认生产缺陷时停止发布。只有所有生产模块在最终快照上验证通过或确属无可执行函数，且至少有实际行为验证通过时，才记录 `behavior-verified`；该标签不等于所有业务需求已经得到完备证明。Integration 自测材料是 Agent 证据，不能代替宿主验收结论。

## 配置与执行边界

- 检索、项目建模沿用已配置的本机代码智能服务和历史仓，不读取实验数据集默认数据库或历史路径。
- 模型地址、名称和密钥来自现有设置与 SecretStorage。Codex 使用独立的临时配置；需要安装可调用的 Codex CLI，并使其支持所选模型的 Responses 接口。启动扩展时可通过 `ADAPTATION_CODEX_COMMAND` 指定独立运行目录中的 CLI，通过 `ADAPTATION_CODEX_HOME` 提供预配置的 Codex 目录。模型端点是否兼容需在企业部署环境验证。
- 编译和固定验收命令只取用户级 `forexplore.backend.compileCommand` / `forexplore.backend.verification`。缺少 SDK、测试框架或依赖会显示实际失败或验证缺口。
- 原骨架不回填；输出副本、报告、协议保存在扩展全局存储的 `project-pipelines/<run-id>/`。临时模型凭据与历史视图在任务结束时清理。
- 取消会传入模型请求、验证预算、测试进程和 Codex 进程树。扩展宿主退出后不支持自动续跑；重启读取为 interrupted，保留报告并重新开始。当前是本机扩展宿主管理，不是可在 VS Code 退出后继续执行的远程任务服务。
- 整个项目与单模块调试均在点击开始后自动执行。单模块保留结果查看和回滚操作。

## 验证

- 自动接线测试覆盖需求和协议传递、多参考选择、同一 Translator 修复、环境故障区分、取消、最终快照验证和资源清理。
- 打包集成测试实际执行 Codex Runtime、进程启动、独立 staging、真实 Node 编译、主动 Integration、新生产文件、Git 提交和报告；CLI 模型输出及 Verifier 判断由确定性测试替身提供。
- 原有流水线测试继续覆盖输出隔离、固定测试保护、验收证据、持久化失败及重启记录。
- 本次没有调用付费真实模型，也没有把模拟测试视为企业 Java / C# 任务的业务验收结果。
